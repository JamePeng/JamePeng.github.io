# JamePeng 的个人博客

个人技术博客，采用吉尔伽美什头像与黑金、深红配色。使用 Node.js 生成静态页面，通过 GitHub Pages 托管；文章管理在本地运行。

## 本地运行

需要 Node.js 20.11 或更高版本。首次使用管理页先安装依赖：

```sh
npm install
npm run admin
```

文章管理：[http://127.0.0.1:4173/admin/](http://127.0.0.1:4173/admin/)；博客预览：[http://127.0.0.1:4173/](http://127.0.0.1:4173/) 。`npm run dev` 也会启动同一个本地服务。使用 Ctrl+C 停止。

## 用管理页添加与修改文章

1. 点击“新增文章”，填写标题、正文和发布日期；支持粘贴带格式的公众号正文，也可以导入 HTML 文件。正文提供加粗、标题、列表、引用、代码块、链接和预览。
2. 也可以在顶部粘贴公众号原文链接，点击“读取文章”。读取到的标题、原始时间、正文、公众号名称和原文链接会自动带入一篇新文章，不会覆盖当前文章。若微信将请求跳转到验证页，管理页会明确提示“微信要求浏览器验证”，并显示打开原文、导入网页的操作入口；不会把它误报为文章链接无效。
3. 在右侧选择发布日期与可选的时分（北京时间），填写分类和标签，按需设为首页精选。自动读取不到原始时间时，必须自行填写。
4. 点击“保存并生成博客”。内容会实际写入本地文件，同时更新首页、文章页、归档、搜索索引、RSS 和 SEO；刷新或重启后仍然保留。
5. 从左侧打开已有文章即可修改日期或正文。只修改日期会保留正文源文件与既有永久链接。

管理页仅在本机服务运行时可写，不依赖浏览器临时存储，不会把写入接口部署到 GitHub Pages。保存会自动备份修改前的文章目录与正文到 `.local-backups/`（Git 已忽略）；如果生成失败，自动恢复源文件。同一篇文章有其他窗口的新修改时，会阻止旧窗口覆盖。

公众号图片默认保留原始图片链接，并以不发送来源页的方式加载；图片能否显示仍取决于原图地址是否可访问。

保存只更新本地博客。确认预览后，将修改与生成文件提交、推送到 GitHub，才会在线上生效。

### 微信要求验证时：导入已保存的原文网页

1. 在自己的 Chrome 或 Edge 中打开公众号原文。如出现验证，自己完成后确认正文可见。
2. 按 `Ctrl+S`，选择保存为 HTML 网页（`.html` 或 `.htm`）；不要保存验证页或 `.mhtml` 单文件格式。
3. 回到管理页，保留顶部原文链接，点击“导入公众号网页”并选择刚保存的 HTML 文件。
4. 管理页在本地提取标题、公众号名称、原始发布时间、正文和图片链接；这一步不会再次请求微信，也不会读取浏览器的登录信息。如果网页缺少原始时间或来源链接，会提示手动补充。检查后再点“保存并生成博客”。

完整 HTML 网页支持最多 50 MB；导入时只保留文章正文，去除网页脚本等无关内容。正文编辑、预览与保存统一支持最多 10 MB。顶部网页导入直接传输 HTML，避免 JSON 转义使上传体积膨胀。正文工具栏的“导入 HTML”适用于最多 10 MB 的正文文件；浏览器保存的完整公众号网页请使用顶部“导入公众号网页”。更新程序后，需要重启 `npm run admin` 并刷新管理页，让服务端和页面一起采用新限制。

### 导入时自动整理排版

管理页默认勾选“导入时自动整理排版”。公众号链接、已保存的公众号网页和正文工具栏的 HTML 文件导入均使用同一套本地规则：清理空段与空标题，修正正文被误当成标题的情况，统一可识别的章节和方法层级，合并相邻完整短句，恢复代码模板的换行，将独立配图与原有图注组合，并把明确的两组概率数值整理成对照。输出沿用当前博客的黑金阅读样式与手机布局。

规则只整理结构，不调用外部 AI 服务、不改写观点、不补造图注或研究结论；无法可靠识别的复杂结构保留原样。正文文字、图片与链接的顺序会在整理前后核对，正文内跳转已有的标题锚点也会保留，重复整理不会反复套样式。标题、发布日期、来源等文章设置不受正文整理影响。导入摘要优先提取开篇段落，避免将目录与代码一起拼接进摘要。取消勾选后，本次导入只做原有的内容清理。

已经导入或正在编辑的文章，可以点击正文上方的“整理排版”，查看调整统计，再点击“预览文章”核对正式阅读效果。“撤销整理”恢复上一次手动整理前的正文，保留其他文章设置；继续编辑正文、导入另一份内容或切换文章后，这一步撤销记录会清除。无论自动还是手动整理，都必须点击“保存并生成博客”才会写入文章与生成页面；保存仍保留修改前备份。更新功能后重启服务并刷新管理页。

“导入公众号网页”会准备一篇新文章，不会直接覆盖已有文章。正文工具栏中的“导入 HTML”仍只替换当前编辑器正文。也可以点击“新增文章”，直接复制粘贴正文并手动填写日期。

## 手动维护文章（可选）

1. 在 `content/` 新建文章 HTML 文件，可直接使用标题、段落、列表与 `<pre><code>` 代码块。为要进入目录的标题添加唯一的 `id`。
2. 在 `content/posts.json` 中添加标题、日期、分类、标签、摘要、文件名与永久地址。文章按 `date` 从新到旧自动排序，无需调整数组顺序。将一篇文章设置为 `featured: true`；可选的 `cardTitle`、`cardDescription` 数组指定精选卡片的分行文案，`cardLabel` 和 `cardNote` 指定插画旁注。
3. 执行 `npm run build` 和 `npm run check`。生成的页面、RSS、搜索索引和站点地图一并提交到仓库。

站点资料和正式域名位于 `content/site.mjs`；文章目录由 `content/posts.json` 维护；公共页面模板位于 `scripts/build.mjs`；样式位于 `css/style.css`；搜索、主题与阅读交互位于 `js/main.js`。管理页位于 `scripts/admin/`。统计数量、分类筛选、年月归档随文章列表生成。

## 搬运公众号文章与修改发布时间

推荐直接在管理页修改日期并保存。也可以编辑 `content/posts.json` 中对应文章的 `date`，然后执行 `npm run build`。首页、文章页、年月归档、搜索索引、RSS 与搜索引擎元数据会同步更新。既有文章日期不会被自动改成搬运当天。下面是字段示意，手动写入 JSON 时请去掉注释：

```js
{
  slug: "my-wechat-article",
  title: "我的公众号文章标题",
  path: "/posts/my-wechat-article/", // 永久链接，与发布日期独立
  date: "2024-05-20 20:30",         // 填公众号原始发布时间（北京时间）
  // updated: "2024-05-25 09:00",   // 可选：确实修改正文时再填写
  source: {                        // 可选：文章页展示公众号原文链接
    name: "我的微信公众号",
    url: "https://mp.weixin.qq.com/s/替换为实际文章地址",
  },
  category: "技术折腾",
  tags: ["随笔"],
  description: "这篇文章的简短介绍。",
  file: "my-wechat-article.html",   // 正文保存在 content/ 下
}
```

- `date` 支持 `YYYY-MM-DD`、`YYYY-MM-DD HH:mm`，也支持带时区的 ISO 时间，例如 `2024-05-20T20:30:00+08:00`。不写时区时按北京时间处理；页面与年月归档也统一使用北京时间。
- `updated` 可省略。只有它晚于发布时间时，页面才显示“最后更新于”；修改 `date` 后，无需为了通过构建而同步改动旧的 `updated`。
- 修改日期不会改动 `path` 或 RSS 文章标识，因此文章链接保持有效。年月归档按现有文章重新生成，已无文章的旧归档页和空目录会清理。
- `source` 可省略；填写后，读者可以从文章页跳转到公众号原文。原文地址必须使用 `https`。
- 日期写错（例如 `2024-02-30`）会在构建前报出具体文章和字段，不会覆盖已生成的页面。

## 发布

所有输出直接生成在仓库根目录。延续该仓库的 GitHub Pages 分支发布方式，选择根目录 `/`；`.nojekyll` 避免 Jekyll 处理静态文件。根目录 HTML 是构建产物，请通过管理页保存或修改 `content/` 后重新生成。线上站点无需 Node 服务、数据库、第三方字体或 CDN。

`npm test` 验证日期、公众号解析、内容清理、写入备份、失败回滚与本地 API；`npm run check` 验证生成页面与链接。

功能包括深浅主题（默认黑金，记忆选择；浅色为羊皮纸与古金配色）、全文搜索（Ctrl/⌘ K）、分类筛选、阅读目录、代码复制、阅读进度、RSS、404 与 SEO 元数据。关闭 JavaScript 后仍能访问文章、归档、关于页和 RSS。

头像原图位于 `assets/avatar.jpg`，首页主视觉、导航、作者卡片与文章署名共用同一文件。金色法阵与装饰由 SVG/CSS 绘制，不依赖外部图片或字体服务。替换头像后无需修改各页面。

项目只保留当前使用的页面、文章、资源、构建与管理工具。旧模板的示例文章、搜索插件、第三方图库、字体和图片已移出项目；真实文章的正文与发布时间保留，2019 年刷机文章带有存档时间提示。本地安装的 `node_modules/` 用于当前管理工具，Git 忽略依赖目录和临时文件。
