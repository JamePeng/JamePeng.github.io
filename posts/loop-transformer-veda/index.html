让模型用同一组层，多想一遍：Loop Transformer 的前沿研究，以及我在 Veda 上看到的机会与边界

同一组层多想一遍，怎样才算把循环变成能力？从公开研究到 Veda 的三组配对实验，记录共享深度的机会、真实成本与验证边界。

JamePeng

原载于 澄鸿AI踢桃

如果一个模型回答不够好，我们通常会想到加参数、加数据、蒸馏更好的模型，或者让它多生成一些思考文字。

我最近反复思考的是另一件事：

能不能让同一组 Transformer 层，在输出下一个 token 之前，对内部状态再处理一遍？把对外的输出token变成内部latent传递优化？

这就是 Loop Transformer 最吸引我的地方。它把「模型有多少套权重」和「一次回答做多少层计算」拆开了。但随着我为 Veda 新架构研究越深入，我越觉得不能把“多转几轮”直接翻译成“更会思考”。同一套权重反复调用，确实可能带来新的计算深度；额外的计算、激活与缓存也一分不会少。真正需要回答的是：多出来的那一轮，能否在同等成本下换来更多正确答案？

注：VEDA为JamePeng个人自用研发的多智能体AI前沿探索模型

一、Loop 改变的，是输出前的计算深度

传统 Transformer 想从 24 层加到 32 层，通常要再增加 8 套独立层。Loop 的另一种做法是重复调用已有层：物理权重仍是那些，逻辑上的执行深度却增加了。

这里的“循环”发生在 hidden state 里，不是让模型把已经写出的答案读回去再改一遍，也不是多生成几段可见的思考文本。对于自回归模型，每预测一个新 token，都要先完成这一轮内部计算。

Veda 当前有两条互补路线。

从零 Veda 随机初始化四个物理 Transformer 块，让它们共享权重执行四轮；Qwen3.8 只提供分词器与聊天协议，没有提供预训练权重。每轮产生的增量进入历史池，下一轮可以重新读取入口表示和历轮增量。

Veda Base v1 则继承 Qwen3.5-0.8B 的预训练权重，把原 24 层中的中段 8 层再执行一次：24 套物理语言层，对应 32 次逻辑层调用。新增训练参数只有 294,920 个，主要是共享 LoRA 与第二遍门控。

这两个模型不能放进同一张成绩表。一个在问“共享深度本身能学到什么”，另一个在问“已有预训练能力上再加一次计算值不值”。

二、公开研究已经越过“能不能训练”，还没给出万能配方

Huginn 把递归深度模型做到 3.5B 参数、约 800B 训练 token，显示同一检查点在部分任务上能从更多测试时计算受益。Ouro 则把循环与深度分配放进大规模预训练。它们说明，Loop 不是只能存在于玩具任务的结构设想。

更关键的新证据来自 SMELT：作者在 MoE 模型中尽量匹配每 token FLOPs、非词表参数和 KV 预算，让中间约一半层重复一次；其计算最优前沿拟合报告，同等损失所需训练 FLOPs 下降约 6.8%—18.0%。这是一项值得认真对待的等预算正结果，但数字来自特定 MoE 设置和损失曲线拟合，不能直接搬到 Veda 的稠密模型上，也不是推理墙钟加速。

LoopMDM 在 masked diffusion 语言模型里也发现选择性重复早中段层的收益；不过它有双向 mask 工作区和不同的生成目标。与 Veda 的自回归模型相比，这是启发，不是可直接套用的效率倍率。DeepLoop 从另一面提醒我们：一套权重被多轮访问时，梯度会汇集到同一参数上，普通独立层的残差缩放未必适合直接照搬。

把这些工作放在一起，我目前得到的不是“循环次数越多越好”，而是三个更具体的问题：重复哪一段、训练时让模型见过哪些深度、为多出来的计算支付了多少真实成本。

三、Veda 的好消息，首先是“确实能学”

从零 Veda 使用一套 40,100 条问答训练数据，完整序列约 1.32 亿 token，其中参与监督的位置约 1.28 亿。5000 次更新恰好让每条成员访问一次。

固定训练成员上的 NLL 从第 1000 步约 3.95 降至第 5000 步约 2.82，说明模型确实在学习；但当时四道原题的自主生成仍没有一题达到严格完成标准。正确前缀下更会预测，不等于从问题出发就能稳定答完。

另一个较早的支路更直观：从不同的第 1000 步父模型出发，反复训练 128 条短问答，到每条访问 60 遍时，125/128 条能按“思考闭合、非空回答、EOS 结束”的格式完成，100/128 条最终答案与参考字符串完全一致。它反驳了“这套骨干根本学不了完整输出”的判断，却只证明训练成员能被拟合，不是新题泛化。

真正让我警惕的是随后的小集实验。从第 5000 步母模型分出相同 128 条继续训练 600 步，固定面板里，被反复访问的 8 道题平均 NLL 从约 3.91 降到 0.04；另 8 道母模型曾见过、但这一阶段未复访的题却从约 4.70 升到 6.05。终点的 8 道自主生成题中，所有全文匹配都来自被反复训练的前 4 道。

这不是 Loop 特有的“遗忘定律”，也不能仅凭 16 道题给退化定因。但它足以改变实验优先级：在庆祝某个控制器多答对一题之前，我必须先搞清楚，究竟是结构让它变好，还是训练数据被反复看了几十遍。

四、把“多想一遍”拆成三组实验

为了知道收益究竟来自哪里，我从同一个第 5000 步母模型分叉，把改动放在三个不同位置：只改中间轮的训练损失、改读历史的 query 或写回时的门控、改四轮写回强度。 下图把每一组自己的基线、介入位置、数据覆盖和终点放在一起。三组可以各自做配对判断；不能把不同数据覆盖和训练实现下的终点分数直接排成架构榜单。

第一组：训练损失接在 R3。

final-only 与 R3 辅助监督两支使用相同顺序的 4,100 条不同训练成员，各续训 500 步、约 1,320 万监督 token。R3 的真实答案只进入辅助 CE，不进入前向状态。原固定面板上，R3 读出 NLL 从 3.733 降到 3.016；最终 R4 却是 2.9685 对 2.9693，12 题自主生成两支均为 0/12 严格完成。

中间状态更容易读出答案，还不能证明少算 R4 可行。

第二组：改变“读”或 R3 的“写”。

在相同 128 条短训练成员上，基线保留共享读写；轮次 query 改动 R2—R4 的 AttnRes 读取；token 门控则缩放 R3 既有候选编辑。每支续训 600 步、约 139 万监督 token。初版门控因起点函数不等价在第 27 步停用，下面只统计重新启动的有效门控支路。

统一固定 8 题面板中，全文匹配分别是 3/8、4/8、1/8。门控曾在第 480 步达到 4/8，到第 600 步反而只剩 1/8；这提醒我不能用某个中途检查点的领先宣布结构胜出。轮次 query 在第 600 步虽多匹配一题，严格完成却从基线的 7/8 降到 6/8。

第三组：保持同一个 MLP 候选方向，改变四轮写回系数。

固定 R3 强度、每轮可学常数、每 token 可学强度三支共享另一套配对实现和相同 batch 顺序，也在 128 条上续训 600 步。固定 8 题全文匹配依次为 3/8、3/8、4/8；每 token 分支严格完成 8/8。

冻结该分支后，只删除学到的 R3 新增强度，全文匹配从 4/8 回到 3/8；只保留 R3 新增强度仍为 4/8。这是一条局部因果线索：R3 状态编辑确实改变了这次生成，却还不能证明四轮都需要可学习控制，也不能证明从头只训练 R3 会复现结果。

这三组还共同受一个更大的边界约束：这些生成题都来自原训练池，小集实验的匹配只发生在反复访问的前四题。接下来需要更大、预先固定的题组与第二种数据顺序，才能判断多出的正确题是否稳定，且没有以其他已见题的退化为代价。

五、再往前一步，才谈得上 RSI

Loop Transformer 的“递归”是一次前向里的重复计算。RSI（递归自我改进）讨论的是更外层的过程：系统提出对自身方法的改变，在独立任务上验证真实收益，保留有效改变，再用改进后的能力改进下一轮。二者可以相互启发，但不是同一件事。

Veda 目前的 TruthHead、Judge 和候选编辑器还没有组成“提出—验证—接受”的可靠在线闭环。评分头的训练标签来自已知答案，离线预测的 NLL 收益也不等于自主生成时的真实正确性。若未来真要把这条路线接到 RSI，我更愿意先要求每一次候选修改都留下独立验证、错→对与对→错、实际计算成本和可继承结果，再讨论连续自我改进。AlphaEvolve 的公开描述展示了外层候选与自动评估怎样结合，但那是系统级算法搜索案例，不是 Veda 已实现的能力。

结语：下一轮要用更严格的对照换答案

我接下来最想完成三件事。

  1. 第一，让“128 条反复学习”和“交错复习其他已见题”在相同监督 token 预算下正面比较，观察新学会的答案是否以覆盖保持为代价。
  2. 第二，从同一 Qwen 起点对比普通 LoRA 与 Veda Base v1 的 Loop＋LoRA，同时报告正确题、训练 GPU 秒和实际解码延迟。
  3. 第三，只围绕 R3 做最小配对：固定强度、常数强度、token 强度，再用第二种数据顺序和更大的预先固定面板复验。

我对 Loop Transformer 的兴趣并没有因这些限制而下降。恰恰相反：当“能训练”“能拟合训练题”“能改变一次生成”和“同成本下更好”被分开以后，真正值得投入的实验才变得清楚。

同一组层多想一遍，只有在多出来的那一遍带来可复验的净正确答案时，才算把循环变成了能力。
