      前段时间使用的端侧部署方式基本都是CPU推理为主，普遍6-9token每秒，感觉没有利用移动端处理器的AI加速单元，近两年无论是联发科ARM还是高通都在强调自家芯片的NPU单元算力的提升，如果能用上加速器的话必然能够让端侧模型的人机交流更加的高效顺畅。

最近，我花了一些时间研究新出的ExecuTorch如何在安卓设备上运行Llama模型，使用Qualcomm的AI加速器来提升推理性能。这对于开发者来说是个很实用的操作，特别是想将大语言模型端侧部署的朋友们！今天就跟大家详细分享一下整个过程，帮你们节省不少时间。

介绍一下ExecuTorch，它是一个用于在移动设备和边缘设备（包括可穿戴设备、嵌入式设备和微控制器）上实现端到端推理功能的解决方案。作为 PyTorch Edge 生态系统的一部分，它能够高效地将 PyTorch 模型部署到边缘设备上。

主要分为三个步骤：

  1. 导出模型：首先，需要将 PyTorch 程序转换为图的形式，这是一种通过一系列运算符（如加法、乘法或卷积）来表达模型的新表示形式。此过程确保模型原有语义不变，并为在内存和计算资源有限的边缘设备上运行模型打下基础。

  2. 编译模型为 ExecuTorch 程序：接着，将导出的模型转换为可执行格式，即 ExecuTorch 程序。这一过程提供了多种优化入口，例如模型压缩（如量化）以减少大小，或者进一步将子图编译为适配设备的硬件加速器以提升延迟性能。同时，它还为内存规划提供了优化空间，能够有效分配中间张量的位置，降低运行时内存使用。

  3. 在目标设备上运行 ExecuTorch 程序：最后，ExecuTorch 运行时载入该程序，执行相应指令并计算输出。由于在前两步中已优化了执行计划，这一步效率较高。其核心运行时（runtime ）轻量化（lightweight ），能够适配多种资源受限的设备。

一、教程概览

这个教程讲的是如何从头到尾构建一个基于Qualcomm AI加速器的安卓演示应用。简单来说，我们要做三件事：

  1. 导出并量化Llama模型：针对Qualcomm芯片的backend后端进行导出和量化模型和分词器，减小模型大小、提升推理速度。

  2. 构建并链接必要库：在安卓平台上通过Qualcomm AI加速器来完成模型推理的库构建和链接。

  3. 构建安卓演示应用：最后是把这一切整合到一个安卓演示应用中，完美运行在安卓设备上。

适配环境（暂不支持Windows端部署）：

  • Linux CentOS

  • QNN SDK v2.26

  • Python 3.10

  • Android SDK r27


二、环境准备

首先我们需要下载并安装几个关键工具：

  • QNN SDK v2.26
  • Android SDK r27
  • 你需要一台搭载Snapdragon8 Gen2/Gen3的安卓手机，Gen1及更早的手机可能兼容，但内存普遍较小且未经过验证。

另外，还需要Llama模型的权重文件（.PTH格式），可以从HuggingFace下载，比如Meta-Llama-3-8B-Instruct。

三、设置ExecuTorch环境

首先，我们使用Conda来管理环境。如果你没有安装Conda，可以先去安装。

创建Conda环境并激活：

conda create -n et_qnn python=3.10.0
conda activate et_qnn

克隆并设置ExecuTorch仓库：

git clone https://github.com/pytorch/executorch.git
cd executorch
git submodule sync
git submodule update --init
./install_requirements.sh

四、配置QNN SDK

设置好QNN SDK后，我们需要将以下环境变量导出并开始构建Qualcomm后端：

export ANDROID_NDK_ROOT=$HOME/android-ndk-r27
export QNN_SDK_ROOT=$HOME/Your-SDK-Root
export EXECUTORCH_ROOT=$HOME/repos/executorch
export LD_LIBRARY_PATH=$QNN_SDK_ROOT/lib/x86_64-linux-clang/:$LD_LIBRARY_PATH
export PYTHONPATH=$EXECUTORCH_ROOT/..

然后使用CMake构建QNN后端：

./backends/qualcomm/scripts/build.sh --release
cmake -DPYTHON_EXECUTABLE=python \
    -DCMAKE_INSTALL_PREFIX=cmake-out \
    -DEXECUTORCH_ENABLE_LOGGING=1 \
    -DCMAKE_BUILD_TYPE=Release \
    -DEXECUTORCH_BUILD_QNN=ON \
    -Bcmake-out .
cmake --build cmake-out -j16 --target install --config Release

五、Llama模型导出

接下来我们需要导出Llama模型，QNN支持导出fp32和int4/int8的量化数据，以及仅限Llama 3的SpinQuant INT4。你还可以选择将模型导出到不同的Qualcomm芯片平台，例如SM8650和SM8550。

如果你需要导出到不同的SoC，只需在导出命令中添加--soc_model参数。例如：

python -m examples.models.llama2.export_llama --checkpoint "${MODEL_DIR}/consolidated.00.pth" \
    -p "${MODEL_DIR}/params.json" \
    --qnn --pt2e_quantize qnn_8a8w -d fp32 \
    --soc_model SM8550 \
    --output_name="llama_sm8550.pte"

如果没有设置--soc_model参数，系统将默认导出到SM8650平台。

六：量化导出（PTQ）

Executorch默认支持PTQ（后训练量化），整个导出过程大约需要20分钟（Llama 3.1 8B）。不过目前仍存在一些精度下降的问题，团队也在努力优化中。需要注意的是，像8B这种大型模型可能需要设备具备16GB的RAM才能运行。

示例：

  • 4位权重量化（4 bits weight only quantize）

python -m examples.models.llama2.export_llama \
    --checkpoint "${MODEL_DIR}/consolidated.00.pth" \
    -p "${MODEL_DIR}/params.json" \
    -kv --disable_dynamic_shape --qnn --pt2e_quantize qnn_16a4w -d fp32 \
    --metadata '{"get_bos_id":128000, "get_eos_ids":[128009, 128001]}' \
    --output_name="test.pte"

对于非常大的模型（例如Llama 3 8B），可能需要进行模型分片，因为Qualcomm的DSP是32位系统，单个文件大小限制为4GB。以Llama 3 8B为例，模型需要分成四个分片，但ExecuTorch会将其打包成一个PTE文件。示例如下：

  • 8位量化，4个分片（8 Bits Quantization with 4 Shards）

python -m examples.models.llama2.export_llama \
    --checkpoint "${MODEL_DIR}/consolidated.00.pth" \
    -p "${MODEL_DIR}/params.json" \
    -kv --disable_dynamic_shape --qnn --pt2e_quantize qnn_8a8w -d fp32 \
    --num_sharding 4 \
    --metadata '{"get_bos_id":128000, "get_eos_ids":[128009, 128001]}' \
    --output_name="test.pte"

在导出Llama模型时，你可能会好奇--metadata标志的作用。 这个标志用于帮助在模型导出时加入适当的特殊标记，从而让运行时更容易检测到结束（EOS）标记。

如果你遇到如下错误：

[ERROR] [Qnn ExecuTorch]: Cannot Open QNN library libQnnHtp.so, with error: libc++.so.1: cannot open shared object file: No such file or directory

可以通过以下几种方法解决：

  1. 安装旧版QNN（如2.23或更早）并从${QNN_SDK_ROOT}/lib/x86_64-linux-clang中复制。
  2. 使用apt-get手动安装。
  3. 使用${QNN_SDK_ROOT}/bin/check-linux-dependency.sh脚本安装。
  4. 使用Conda安装：
conda install -c conda-forge libcxx=14.0.0

安装完成后，检查libc++.so.1是否已添加到LD_LIBRARY_PATH或系统库路径中。

七：分词器的转换

对于Llama 2和Llama 3，分词器的处理方式略有不同。在导出模型之前，确保正确转换分词器。

Llama 2 分词器转换：使用以下命令将tokenizer.model文件转换为二进制格式tokenizer.bin：

python -m extension.llm.tokenizer.tokenizer -t <tokenizer.model> -o tokenizer.bin

Llama 3 分词器转换：对于Llama 3，直接将tokenizer.model重命名为tokenizer.bin即可：

mv tokenizer.model tokenizer.bin

八：将模型（Model ）与分词器（Tokenizer）推送到设备

模型和tokenizer准备好后，可以将它们推送到设备上：

adb shell mkdir -p /data/local/tmp/llama
adb push llama-exported.pte /data/local/tmp/llama
adb push tokenizer.bin /data/local/tmp/llama

九、构建安卓AAR库

接下来，我们需要将构建好的模型推送到安卓设备上，并构建安卓的AAR库。首先，设置以下环境变量：

export ANDROID_NDK=<path_to_android_ndk>
export ANDROID_ABI=arm64-v8a

然后，构建安卓的Java扩展代码：

pushd extension/android
./gradlew build
popd

接着运行命令，设置JNI库：

pushd examples/demo-apps/android/LlamaDemo
./gradlew :app:setupQnn
popd

你也可以直接运行根目录下的脚本，完成配置：

sh examples/demo-apps/android/LlamaDemo/setup-with-qnn.sh

此脚本将自动配置所需的核心ExecuTorch、Llama2/3和Android库，构建它们并将其复制到jniLibs目录下。

注意：如果你在不同的机器上构建Android应用（例如在MacOS上进行Android应用的开发，但在Linux上为QNN后端构建并导出），请确保在构建Android应用之前，将setup-with-qnn.sh脚本生成的AAR文件复制到 examples/demo-apps/android/LlamaDemo/app/libs 目录中。

十、运行Android Demo应用

在运行Llama Demo应用之前，请确保你的Android手机芯片与该演示兼容（支持SM8650或SM8550芯片）。

如果你在与构建Android应用不同的机器上运行setup-with-qnn脚本，请确保将脚本生成的AAR文件复制到examples/demo-apps/android/LlamaDemo/app/libs目录中。

运行Android Demo应用的两种方式

方法一：通过Android Studio（推荐）

  • 打开Android Studio。

  • 选择“Open an existing Android Studio project”并导航到examples/demo-apps/android/LlamaDemo目录。

  • 运行应用（快捷键 ^R），这将构建并在手机上启动应用。

方法二：通过命令行

如果你不想使用Android Studio界面，可以直接通过Gradle命令行构建应用。首先，你需要设置Android SDK路径，并运行以下命令：

export ANDROID_HOME=<path_to_android_sdk_home>
pushd examples/demo-apps/android/LlamaDemo
./gradlew :app:installDebug
popd
