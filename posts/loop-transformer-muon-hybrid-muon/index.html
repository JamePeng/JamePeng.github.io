我从 Loop Transformer 实验中探索更高效的 Muon 优化器 | Hybrid Muon 正式开源

从2024年开始训练 Veda 时，我持续为它整理了一套高质量 CoT（思维链）问答数据。每道题除了最终答案，还保留了解题过程。我写的 Qwen 监督微调脚本，就是用这些数据训练模型，让它学习怎样把一道题一步步解出来。

这也让我对另一个问题产生了兴趣。模型可以用一连串词元把推导写在纸面上。那在写出下一个词元之前，能不能让它在内部多算几轮，利用上一轮留下的中间结果，把下一步预测做得更好？

为了研究这个问题，我结合当下Loop transformer的研究，从零训练了一条 Veda 循环模型分支。这次实验用的是一个约 3.09 亿参数的语言模型。它有 4 个共享的 Transformer 块，每个块都参与 4 轮计算。这样一来，一次前向传播里有 16 次块调用，而我只需要训练这 4 个块的权重。

训练中有个现象让我把注意力从模型结构转到了优化器上。给同一个模型反复看 128 条样本，一种训练方案把眼前的题学得更快，另一种却让模型在旧题上退步得更少。两边用的是同一份起始权重、同样的数据顺序，连投影矩阵的学习率都写着 5e-5。差别究竟出在哪一步？

我回头量了那 28 个矩阵

当时，我把给 Veda 写的 Qwen 微调脚本里的混合优化器取出来，接进了循环模型。一组全部使用 AdamW，另一组只把 28 个投影矩阵交给 Muon，其余可训练参数继续用 AdamW。

跑完 200 步，AdamW 在这 128 条样本上的损失更低。但是，拿出另外 32 条模型以前见过、这次没有复习的样本，混合方案的损失上升得更少。我想知道，Muon 是选了更合适的更新方向，还是那些矩阵每一步本来就动得更小？

要回答这个问题，得看训练脚本里的 optimizer.step()。

模型读入题目和已有的回答前缀，预测下一个词元。它给参考词元的概率越低，损失就越大。反向传播根据损失算出每个权重的梯度。对 Veda 来说，同一份权重在四轮里反复使用，各轮产生的梯度会累加。等到执行 optimizer.step()，优化器才根据梯度和历史记录，把这一次改动写回权重。

AdamW 为每个权重元素保存两份统计，一份反映最近的梯度方向，另一份估计梯度通常有多大，再据此调整步幅。Muon 把整张投影矩阵的更新放在一起处理，结合动量做近似正交化，减弱少数强方向对更新的支配。学习率相同，乘上学习率之前的更新量也可能相差很大。AdamW 原论文 · Muon 原始设计

我逐个计算了那 28 个矩阵首步更新量的均方根，再取中位数。AdamW 组是 4.9963e-5，早期混合方案是 1.3292e-6。两组都设了 5e-5 的矩阵学习率，AdamW 组第一步的实际更新幅度却是混合组的约 37.6 倍。 到第 200 步，差距缩到了约 7.6 倍。

这给早期的损失曲线提供了另一种解释。混合方案对旧样本退化得少，至少有一部分可能来自更小的矩阵步幅。此后做对照，我除了看学习率和损失，还会记录权重实际改了多少。

早期还有一轮 500 步对照。我挑出保持归一化权重衰减和模型修正机制设置相同的四组，只看矩阵更新方式与学习率。矩阵学习率同为 5e-5 时，原生缩放组在 128 条训练样本上的损失为 1.5214，论文缩放组为 0.1141，AdamW 为 0.2314。但原生缩放组对旧样本的损失最低。换一种缩放，拟合与保持之间的取舍就变了。

再跑 500 步，把矩阵学习率分成三档

我在同一张 RTX 5090 上做了四组对照。一组使用 AdamW，另外三组让 Muon 更新那 28 个矩阵，采用论文中的矩阵缩放方式，分别试三档学习率。每组从同一个检查点出发，按相同的批次顺序训练 500 步，使用 FP32 参数和 BF16 自动混合精度。

这一轮固定混合组的缩放方式，只调 28 个投影矩阵的学习率。四组其余参数都由 AdamW 以 1.5e-5 更新。下表给出第 500 步的 NLL，数值越低，模型给参考文本分配的概率越高。对照值取自本轮自己的 AdamW 运行。

三档 Hybrid 在 500 步的新样本损失都低于同轮 AdamW。把矩阵学习率从 2.5e-5 提高到 5e-5，训练损失从 0.2575 降到了 0.1131，新样本损失却从 5.6558 升到了 5.8344。把各次评估连起来，还能看到四组的新样本损失最后都高于共同起点 4.7602。这轮只完成了一种批次顺序，不能据此确定通用的最佳学习率。

最后取矩阵学习率同为 5e-5 的两组看显存。这次实测，峰值显存少了约 208 MiB。28 个矩阵共有 54,525,952 个参数，AdamW 为它们维护两份矩估计缓冲区，Muon 维护一份动量缓冲区。按每个 FP32 元素 4 字节计算，这个差值可以从模型结构里算回来。

这轮实验用的是固定的一种批次顺序。它让我看到了这套配置下的显存和拟合差异。Qwen 上的训练吞吐量、达到同样损失需要多久，还要在 Qwen 上单独测。项目实验记录

DeepSeek 和 Kimi，分别把 Muon 用在了哪里？ 做完这组对照，再读大模型的训练报告，我会特别留意“使用 Muon”后面的细节。

DeepSeek-V4.1-Flash 在预训练时做了三种安排。线性变换参数由 Muon 更新，RMSNorm 权重等非矩阵参数用 AdamW，词嵌入和预测头则采用另一种叫作 Sinkhorn-balanced update 的方法。词嵌入和注意力投影都可能是二维权重，光看形状，还真猜不出团队给它们选了哪个优化器。DeepSeek-V4.1-Flash 技术报告

Kimi K3 系列让我留意到另一层选择。K3 在预训练中对注意力投影采用 Per-Head Muon。Q、K、V 投影矩阵里包含多个注意力头，团队把对应的动量矩阵按头切开，每个头分别做正交化。即使已经决定让某张矩阵用 Muon，还有“整张一起处理，还是按头处理”的区别。后来的 K3.1 Pro 是从 K3 经大规模联合强化学习得到的后训练版本，这里的分头更新细节来自 K3 的预训练报告。Kimi K3 技术报告 · Kimi K3.1 Pro 官方模型卡

小米的 MiMo-V2.6 又多考虑了一件事：什么时候换。团队到了中期训练，才把隐藏层矩阵切换到带行范数控制的 Muon 变体 Muown，词嵌入、输出头和专家路由器则继续用 AdamW。MiMo-V2.6 技术报告

我为什么把 Hybrid Muon 独立开源

早期实现放在为 Veda 服务的 Qwen 微调脚本里。迁到循环模型时，我需要把共享块的权重名映射到投影分组，还得确认同一个矩阵虽然用了四轮，在优化器里只收了一份。回到 Qwen，冻结几层或者多挂一个预测头，又会改变实际参与训练的参数，导致每次我新的脚本都得不断重新配置很麻烦，也不方便我跨训练服务器部署。

我想把这些核对工作从训练脚本里提出来。于是有了现在的 Hybrid Muon。手上已经有模型，一行代码接入训练。手边只有权重文件，一条命令预览 Qwen 分组，非常方便的使用。

https://github.com/JamePeng/hybrid_muon

已经有 PyTorch 模型，只想接入训练

这种用法只需要安装 hybrid_muon。环境要求为 Python 3.10+、PyTorch 2.10+。

python -m pip install "git+https://github.com/JamePeng/hybrid_muon.git"

模型加载好，挂载需要的模块、设置好哪些参数参与训练，再把模型传给优化器。导入之后，创建优化器只需一行。

from hybrid_muon import HybridMuonAdamW

optimizer = HybridMuonAdamW(model)

匹配规则的注意力和前馈网络投影由 Muon 更新，其余可训练参数由 AdamW 更新，两边的学习率可以分别设置。接下来就在训练循环中调用 optimizer.step()。如果想核对当前模型的实际分组，直接检查内存里的 model 即可，这一步也只需要 hybrid_muon。

from hybrid_muon import inspect_model

print(inspect_model(model))

只有本地权重，想先用 inspect 看分组

这种用法需要从磁盘读取 .safetensors 文件，所以安装命令末尾多了一个独立的包 safetensors。第一次使用可以把两个包一起装好。

python -m pip install "git+https://github.com/JamePeng/hybrid_muon.git" safetensors

把下面的路径换成自己的模型目录，就能预览分组。

python -m hybrid_muon inspect "/path/to/Qwen3.5-4B"

这条命令在 CPU 上读取张量名称和形状，无需把权重加载到显存。报告会列出每组的张量数、参数量占比、默认学习率和权重衰减。加上 --verbose，可以逐个核对权重名。

这两种检查为什么都值得保留？以我手里的 Qwen3.5-4B 为例，按检查点内所有权重都可训练来统计，207 个张量匹配 Muon，占已存参数量的 78.81%。其中 7 个投影来自多词元预测头（MTP）。如果训练脚本只加载主干，实际进入 Muon 组的就是 200 个。命令行能告诉我文件里存了什么，inspect_model(model) 能告诉我这次训练真正会更新什么。

Qwen 分组实例

我最初想知道，共享的四个块多算几轮，Veda 能从中学到什么。沿着训练曲线往下追，最后查到了 28 个矩阵在第一步各自动了多少。把这个项目发布出来，是希望下一位做类似实验的人，可以把时间用在自己的问题上。

Hybrid Muon 0.1.1 已按 Apache-2.0 许可开源。 如果你的模型里有哪一层分组和预期不同，欢迎把模型名、加载方式和那几条张量名贴到 Issue，我们对着具体的权重讨论。项目仓库 · [GitHub Issues](https://github.com/JamePeng/hybrid_muon/issues)
