Looped Transformers：模型不是在“多算几层”，而是在学会反复思考

模型早期循环与后期循环之间的差异，能否成为有价值的计算信号？从 LoopCD 出发，理解反复计算、状态差分与隐空间推理。

JamePeng

原载于 澄鸿AI踢桃

最近我一直在关注 Looped Transformers。

它让我感兴趣的地方，不只是“把同一组 Transformer 层重复跑很多次”这么简单。 真正值得关注的是另外一个问题：

如果一个模型可以对同一份内部状态反复加工， 那么这些重复计算之间，到底发生了什么？ 是在机械地多算几遍？ 还是说，模型真的形成了一条类似“思考轨迹”的东西？

最近一篇论文《Decoding Looped Transformers Better for (Almost) Free》给出了一个非常有意思的答案。

它发现： 模型早期循环和后期循环之间的差异，本身就是一种有价值的信息。 甚至可以直接拿来提高模型的推理结果。

一、什么是 Looped Transformer？

传统 Transformer 可以简单理解成：

输入 → 第1层 → 第2层 → 第3层 → …… → 输出

每一层都有自己独立的参数。 而 Looped Transformer 不一样。 它更像：

输入 → 同一个计算模块 → 再算一次 → 再算一次 → 再算一次 → 输出

也就是说，同一组参数被重复使用。 如果写得更直观一点：

第1轮状态 → 第2轮状态 → 第3轮状态 → …… → 最终状态

这里最有趣的地方在于： 这些中间状态并不是废料。 模型第1轮已经有一个初步判断，第4轮可能更准确，第8轮又进一步修正。

这就有一点像人思考问题：

  • “我最开始觉得是 A。”
  • “等等，可能不对。”
  • “结合另外一个条件，应该是 B。”
  • “再检查一下，B 更合理。”

Looped Transformer 把这种“不断修正内部状态”的过程，搬进了神经网络内部。

二、一个很反直觉的发现：早期“错误答案”也有价值

通常我们运行一个模型，只关心最后一次计算结果。 比如循环 16 次：

h1 → h2 → h3 → …… → h16

最后只保留 h16。 前面的 h1 到 h15 全部丢掉。 但 LoopCD 这篇论文提出了一个很有意思的问题：

为什么要丢掉？

因为 h1 其实代表了：

“模型少思考一点时会怎么回答。”

而 h16 代表：

“模型多思考一会儿之后会怎么回答。”

于是：

最终状态 - 早期状态

实际上就在告诉我们： 额外的计算，到底让模型改变了什么。 举个简单的例子。

模型最开始觉得：

  • A：40%
  • B：38%
  • C：22%

经过更多循环以后变成：

  • A：55%
  • B：28%
  • C：17%

那么额外计算明显在做一件事： 提高 A，降低 B 和 C。

LoopCD 的想法非常简单： 既然模型一直在往这个方向修正，为什么不顺着这个方向再推一点？ 这就是它的核心。

三、LoopCD 本质上是在问：多想一会儿，到底改变了什么？

我觉得可以用一句话概括 LoopCD：

“把模型多思考几轮产生的变化方向，再利用一次。”

如果把早期状态叫 Weak，最终状态叫 Strong，那么：

Strong - Weak

就是“额外计算产生的变化”。 然后 LoopCD 做的是：

Strong + 一点点这个变化方向

这也是为什么它几乎不需要训练新的模型。 早期模型和后期模型，本质上就是同一个模型。 只是一个“少算了几轮”，一个“多算了几轮”。

这件事其实很妙。 因为过去我们经常把“模型能力”理解成一个静态东西。 但在 Looped Transformer 里面，能力开始和“计算时间”绑定起来了。

不是简单地： 这个模型聪不聪明。 而是：

  • 给它 2 轮计算时，它想到这里。
  • 给它 8 轮计算时，它想到那里。

那么这两者之间的差异，就是“额外思考带来的增量”。

四、这其实和 Contrastive Decoding 很像

Contrastive Decoding 的经典思路，是准备两个模型：

  • 一个弱模型。
  • 一个强模型。

比如： 小模型认为某个词很合理。 大模型却认为另外一个词更合理。 那么两者之间的差异，往往能反映出“大模型真正多学到了什么”。

简单来说：

强模型 - 弱模型

得到一个能力差异。 LoopCD 做的事情非常像。 但它甚至不需要两个模型。 它直接把：

  • 早期循环，当成弱模型。
  • 后期循环，当成强模型。

于是就变成：

少量计算的自己
对比
更多计算的自己。

我觉得可以把它称作一种：

“Self-Contrastive Decoding”。 模型在和“刚才那个还没想明白的自己”做对比。

五、它和 DoLa 又有什么区别？

DoLa 也是一个很有意思的方法。 它观察普通 Transformer 的浅层和深层。 浅层可能还只是形成一些比较粗糙的判断。 越往深层，语义和知识逐渐成熟。

所以 DoLa 会比较：

浅层预测
和
深层预测

然后利用两者的差异帮助解码。 这和 LoopCD 非常像。 但两者有一个关键区别。

普通 Transformer 是：

Layer 1 → Layer 2 → Layer 3

每一层都不一样。 Looped Transformer 则是：

同一个 Block → 同一个 Block → 同一个 Block

也就是说，DoLa 看的是：

“模型不同加工阶段之间有什么差别。”

而 LoopCD 看的是：

“同一个计算规则多执行几次以后，状态发生了什么变化。”

后者其实更像“迭代”。 也更接近我们通常理解的“思考过程”。

六、为什么我觉得它和 diffusion 的 CFG 也很像？

如果你用过 Stable Diffusion，一定听说过 CFG，也就是 Classifier-Free Guidance。 它里面有两个预测：

  • 一个是不带提示词条件的预测。
  • 一个是带提示词条件的预测。

然后用：

Conditional - Unconditional

得到“提示词到底改变了什么”。 再把这个方向放大一点。 最终生成结果就会更符合提示词。 LoopCD 的逻辑几乎一样。

只不过它比较的不是：

有条件 vs 无条件

而是：

多计算 vs 少计算

所以可以这样理解：

CFG 在问： “加上条件以后，模型改变了什么？”

LoopCD 在问： “多想几轮以后，模型改变了什么？”

这是我觉得非常值得关注的统一视角。 它们背后都在利用一种“差分”。

七、真正让我感兴趣的是：这个差分是不是“思考方向”？

这里开始进入更有意思的部分。 假设 Looped Transformer 每一次循环都产生一个内部状态： 

h1
h2
h3
h4
……

那么：

h2 - h1

表示第2轮相对第1轮改变了什么。

h3 - h2

表示第3轮又改变了什么。

如果这些变化不是随机的，而是在不断：

  • 修正错误。
  • 整合约束。
  • 完成计算。
  • 检查答案。

那么这些“状态差分”就可能不只是神经网络内部的数值变化。 它们可能对应一种：

Latent Reasoning Update。 也就是： 隐空间里的“思考动作”。

这也是 recurrent latent reasoning 最近越来越有意思的原因。 传统 Chain of Thought 是把推理过程写出来： 

第一步……
第二步……
第三步……

而 latent reasoning 尝试做的是： 不一定把所有步骤变成文字。 模型直接在隐藏状态里完成一部分推理。 于是：

显式 CoT：

文字 → 文字 → 文字 → 答案

可能逐渐变成：

Latent State 1 → Latent State 2 → Latent State 3 → 答案

这时 Looped Transformer 就不再只是一个网络结构。 它更像一个“内部反复计算的工作区”。

八、LoopCD 甚至让我想到一个更激进的方向：预测未来的思考

LoopCD 现在做的事情其实还很简单。 它看到：

模型从 h1 走到了 h8。 于是根据 h1 → h8 的方向，再往前推一点。

这其实很像物理里的“速度”。 如果一个物体过去一直往右移动，我们可以预测它下一刻大概率还会继续往右。 那么未来是不是可以进一步研究：

  • 不仅看模型现在在哪里。
  • 还看它的“速度”。
  • 甚至看它的“加速度”。

比如：

  • 第6轮到第7轮改变了什么。
  • 第7轮到第8轮改变了什么。

如果两个方向越来越一致，我们是不是可以直接预测： 第9轮、第10轮、第11轮可能到哪里？

这样就可能出现一种非常有趣的计算方式：

  • 只真正运行一部分循环。
  • 剩下几轮，不完全计算。
  • 而是预测它的 latent trajectory。

也就是：

真实计算 + 虚拟计算。

从这个角度看，LoopCD 可能只是最简单的一阶版本。

九、所以 Looped Transformer 真正值得关注的是什么？

我觉得不是“循环网络重新流行了”。 也不是“模型多跑几遍效果更好”。 更值得关注的是： 模型内部可能正在出现一种新的“计算时间”。

普通 Transformer 的深度更像空间：

Layer 1、Layer 2、Layer 3。

而 Looped Transformer 的 recurrence 更像时间：

  • 第1次思考。
  • 第2次思考。
  • 第3次思考。
  • 第8次思考。

于是我们开始可以研究一个以前很少被单独拿出来讨论的问题：

多给模型一点计算，它的内部表示到底会往哪里移动？

这件事情甚至可以写成一句非常有意思的话：

“模型的答案重要，但模型改变答案的方向，可能同样重要。”

十、我目前最关注的一个问题

LoopCD 已经说明：

Early Loop → Late Loop

这条方向是有预测价值的。 但它还没有真正证明： 这个方向就是“推理”。

因为里面可能混合了很多东西：

  • 语义修正。
  • 置信度变化。
  • 事实回忆。
  • 句法调整。
  • 答案校准。
  • 真正的逻辑推理。

所以我觉得接下来最值得研究的问题不是：

LoopCD 还能提高几个点？

而是：

Looped Transformer 每一轮 hidden state 的变化，到底代表什么？

如果未来可以证明：

h2 - h1
h3 - h2
h4 - h3

这些变化能够稳定对应：

  • 理解问题。
  • 建立约束。
  • 执行计算。
  • 验证假设。
  • 修正答案。

那么意义会非常大。 因为到了那个时候，我们研究的就不再只是：

“模型思考后的结果是什么。”

而是：

“模型思考这个动作本身，在 latent space 里长什么样。”

这可能才是 Looped Transformers 真正有意思的地方。
