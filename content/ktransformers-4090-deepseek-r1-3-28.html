深度优化背后的技术细节

NUMA节点优化：KTransformers在Intel Xeon Gold CPU上进一步优化了NUMA节点的使用，避免了跨节点数据传输的开销。通过将关键矩阵复制到两个NUMA节点上，尽管会增加内存消耗，但极大地提升了预填充和解码的速度。不过，这种方法会导致内存占用激增，并且加载权重时可能会变慢，所以在加载时需要保持耐心，并关注内存使用情况。未来，KTransformers团队还计划进一步优化这个巨大的内存开销。

CPU/GPU混合推理：DeepSeek模型的MLA操作符计算密集型十足，虽然可以通过CPU来执行所有任务，但将重计算任务卸载到GPU上，会带来巨大的性能提升。KTransformers通过CPU/GPU混合推理，充分发挥了CPU和GPU的优势，使推理速度得到了大幅提升。

性能提升的来源：

  1. 注意力/专家分层卸载：与传统的层级或KVCache卸载不同：
    KTransformers将专家计算卸载到CPU，而MLA/KVCache计算卸载到GPU，这与DeepSeek的架构完美契合，能实现最佳效率。

  2. Intel AMX优化：KTransformers通过优化的AMX加速内核，使得模型推理速度比现有的Llama.cpp实现快了数倍。该内核经过精心调试，确保了在硬件上能够最大化性能。

AMX 指令是Intel至强XEON可扩展处理器内核上的专用硬件模块，有助于优化和加速依赖矩阵数学的深度学习训练和推理工作负载。使 AI 工作负载能够在 CPU 上运行，而不是将其分载到独立加速器，从而显著提高性能。其架构支持 BF16（训练/推理）和 int8（推理）数据类型，包括两个主要组件：

  • Tile：由 8 个二维寄存器组成，每个寄存器大小为 1 KB，用于存储大数据块。
  • Tile Matrix Multiplication (TMUL)：TMUL 是连接到 Tile 上的加速器引擎，为 AI 执行矩阵乘法计算。
  • 与采用 FP32 的第三代英特尔® 至强® 处理器相比，采用英特尔® AMX BF16 的第五代英特尔® 至强® Platinum 8592+ 实现了高达 10.7 倍的实时语音识别推理性能提升和 7.9 倍的性能功耗比提升。

3. 为何选择Intel CPU：Intel是目前唯一支持AMX指令集的CPU厂商，AMX指令集提供的性能比单纯的AVX指令集有着显著的优势。

如何跑在本地？

如果你也想体验这种本地推理加速，只需根据以下步骤进行配置：

V0.2版：单插槽版本（32核）

git clone https://github.com/kvcache-ai/ktransformers.git
cd ktransformers
git submodule init
git submodule update
numactl -N 1 -m 1 python ./ktransformers/local_chat.py --model_path <your model path> --gguf_path <your gguf path>  --prompt_file <your prompt txt file>  --cpu_infer 33 --max_new_tokens 1000
<when you see chat, then press enter to load the text prompt_file>

V0.3版：双插槽版本（64核）

wget https://github.com/kvcache-ai/ktransformers/releases/download/v0.1.4/ktransformers-0.3.0rc0+cu126torch26fancy-cp311-cp311-linux_x86_64.whl
pip install ./ktransformers-0.3.0rc0+cu126torch26fancy-cp311-cp311-linux_x86_64.whl
python -m ktransformers.local_chat --model_path <your model path> --gguf_path <your gguf path>  --prompt_file <your prompt txt file>  --cpu_infer 65 --max_new_tokens 1000
<when you see chat, then press enter to load the text prompt_file>

详细参数解析

在使用KTransformers框架时，有一些重要的参数设置需要注意。下面将详细介绍这些参数的含义，以及如何根据实际情况进行配置：

1.<your model path>

这个参数可以是本地路径或是在线Hugging Face路径。例如，你可以直接在本地指定模型路径，也可以使用在线路径，例如deepseek-ai/DeepSeek-V3，这会自动从Hugging Face下载对应的模型文件。如果你选择在线路径，但遇到网络连接问题，可以使用镜像站点（如hf-mirror.com）来加速下载过程或解决连接问题。

2.<your gguf path>

这个参数是指你需要加载的gguf文件路径。gguf文件通常是大型的预训练模型文件，所以推荐先下载到本地，然后指定本地路径以提高加载效率。下载后，你可以根据需要量化模型以减小文件大小（例如，使用8-bit量化）。

注意：<your gguf path>是文件夹路径（而不是文件本身），指向模型权重文件夹。

3.--max_new_tokens 1000

这个参数控制模型生成的最大输出token数，即模型一次性生成的最大回答长度。如果你发现模型生成的回答被截断，可以通过增加这个数值来生成更长的回答。

重要提示：增加--max_new_tokens 的值会导致内存占用（OOM，Out of Memory）增大，从而可能影响推理速度。若内存不足，模型生成速度会变慢，因此需要根据硬件配置适当调整。

4.numactl -N 1 -m 1

这个命令用于优化模型在多NUMA节点（Non-Uniform Memory Access）上的性能，避免了数据在多个节点之间传输的开销。

-N 1 ：指定模型运行在NUMA节点1（即第一块处理器上的内存）。 -m 1 ：指定模型运行在物理内存1上（即第一块内存）。 通过这种方式，KTransformers能够减少内存传输延迟，从而提高推理速度。

5.--force_think true

如果你正在测试DeepSeek-R1模型，并且遇到模型跳过推理（即模型没有“思考”或者“回答”不完整），你可以通过添加此参数来强制模型进行完整的推理。这个参数会强制模型执行推理过程，不跳过任何步骤，确保模型充分计算并给出回答。
